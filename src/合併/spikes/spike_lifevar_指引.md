# SPIKE變數閘 —— `Variable Value` 能不能取代命旗？（2026-09-01）

前情：選完角色後，Gaia 720「九環旗」的第1命旗建在 `life_cells[0]`＝(232,239)，正好是原作技能表
「佛」那一格（ref 7982、const 285），桿子把該格遮住；720 又是原作的任務道具，玩家看到會以為
觸發了什麼。移欄查無好格（角落僅 229/239 兩欄乾淨、外圍 204–208 落在極練場活動區、
(206,235) 還是斬狂生成格），故改走變數。

**要驗什麼**：`spike_killvar` 已實證「兩法皆過」（見 `merge_spec.yaml` killvar 段），
即 `Compare Variables`、`Variable Value` 的 **≥ 對常數**、`Change Variable ADD` 都可用。
命旗變數化多出四件沒人驗過的事，這支只測這四件：

1. **EQUAL 比較**——命數是等值選路（`V==L` 才跑第 L 命那份），不是門檻比較
2. **SET 覆寫**——換命要蓋掉舊值（killvar 只用過 ADD）
3. **晚啟觸發**——◇命 副本開場停用、由復活鏈 Activate 後才吃閘
4. **looping 觸發**——原作 18 支迴圈觸發也帶命旗條件

（`spike_objhp` 曾以「變數路線作廢」收尾，敗因歸給 `MODIFY_VARIABLE_BY_ATTRIBUTE` 讀不到血量；
本 spike 把寫入與讀取從屬性讀取中隔離，順便替那個歸因補一道交叉驗證。）

## 怎麼跑

單人 → 劇情 → **SPIKE變數閘**。全程約 25 秒，只看聊天列的標籤，最後點畫面中央的「迴圈靶」看血量。

| 秒 | 發生什麼 | 對應命旗的哪個用法 |
|---|---|---|
| t3 | `SET V=1`＋建旗A | 選角建第1命旗 |
| t6 | 讀 V==1 / V>=1 / 旗A | 第1命閘門判斷 |
| t9 | `SET V=2`＋撤旗A建旗B＋啟動「晚啟」與「迴圈」觸發 | 換命：撤舊旗建新旗、啟動 ◇命 副本 |
| t12 | 讀 V==2、驗 V==1 已不成立、讀旗B | 第2命閘門、舊命熄火 |
| t15 | `SET V=0`＋撤旗B | 末命撤旗 |
| t18 | 讀 V==0、驗 V==2 已不成立 | 熄火後全家族不再觸發 |

## 判讀

**應該看到（8 行，缺一行都要回報）**：

| 標籤 | 意思 |
|---|---|
| `[P]` | 訊息通道正常（沒有這行＝測試檔壞掉，別看下面） |
| `[A1]` | `Variable Value` EQUAL 有效 ← **本 spike 的主命題** |
| `[A>=]` | `LARGER_OR_EQUAL` 也有效（未來 lives≥N 的寫法可用） |
| `[B1]` | 旗閘讀到（陽性對照：這行有、`[A1]` 沒有 ＝ 變數路線壞） |
| `[A2]` | SET 覆寫有效（換命語意成立） |
| `[A3]` | 開場停用、後來才 Activate 的觸發也吃得到變數閘（◇命 副本的用法） |
| `[B2]` | 旗閘轉移正常（對照組跟得上） |
| `[A0]` | SET 0 歸零有效（末命熄火語意成立） |

**一行都不該出現的**：

| 標籤 | 代表 | 後果 |
|---|---|---|
| `[X1]` | V 應為 1 時 `V==2` 也成立 | EQUAL 沒在比較（條件恆真）→ 變數化不可用 |
| `[X2]` | SET 後舊值仍成立 | SET 不是覆寫 → 換命會多命齊開 |
| `[X3]` | 歸零後舊值仍成立 | 末命熄不掉 |
| `[XB]` | 旗B 撤了還讀得到 | 連對照組都不準，測試檔本身有問題 |

**迴圈靶血量**（t21 對帳那行提示的）：

| 觀察 | 結論 |
|---|---|
| 血量 < 30000 | `[A迴]` looping 觸發的變數條件每輪都有效（原作 18 支迴圈觸發帶命旗條件的用法成立） |
| 血量 == 30000 | looping 沒吃到變數條件 → 那 18 支要留旗或另外處理 |
