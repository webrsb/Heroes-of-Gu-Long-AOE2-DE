## 血量條件 spike（`spike_objhp.py` → `SPIKE血量條件.aoe2scenario`，2026-08-31，待回報）

起因：東碼頭「精力不足封鎖」（`X船血東`：`OBJECT_HP` 英雄 ref ≤100,000 → 拆掉確認與扣費）在遊戲內完全沒攔到，
血不夠照樣被扣、當場死。

**v1 作廢的教訓（使用者指出「必須是負血，超過 33272 就會死亡」）**：v1 用 `Change Object HP ADD 200000`
想造 20 萬上限——上限是 **int16、天花板 32767**（見 `古龍921_DE遷移記錄.md`：超過一點就回繞致死；
南宮尾葉四人各 +10000 → 40192 回繞成負，當前血量等比縮放後亦負 → 王死亡），20 萬回繞成 3392，
再打 15 萬傷害就開場死光，整份 v1 量不到東西。**正確模型：上限留 int16 小值，當前血量用負傷害灌大**
（current HP 是 float32，單位不被夾）。

| 組 | 驗什麼 | 正常應該 |
|---|---|---|
| A | 門檻 100,000（超 int16）——條件的 quantity 吃不吃這麼大 | A1 A3 ✓；A2 A4 ✗ |
| E | 門檻 30,000（int16 內）——分辨「條件壞」還是「數值太大」 | E2 ✓；E1 E3 ✗ |
| C | s39 跨命 OR 展開後「≤ 才封鎖」的極性（大／小門檻各一組） | C1 C3 ✓；C2 C4 ✗ |
| F | 變數路線：`MODIFY_VARIABLE_BY_ATTRIBUTE` 讀 HIT_POINTS（按玩家＋單位種類、**不吃 ref**、免疫 OR 展開）＋`VARIABLE_VALUE` 比較 | F1 F3 ✓；F2 ✗ |
| D | 同 tick 啟動順序：大 id 封鎖器攔不攔得住小 id 扣費 | D1 出現＝攔不住（封鎖必須早一個 tick）；D2 必出現 |

六隻單位開場灌好血（U1 約 5 萬／U2、U3 約 15 萬／U4 未灌約 3 萬 2／F低 長槍兵 5 萬／F高 弓兵 15 萬），
t=6 判定 A/E/C、t=8 讀變數、t=10 判定 F、t=14 跑 D、t=20 印對帳。

### 結果（2026-08-31 使用者實測）

- **A1 ✓ A3 ✓、A2 A4 ✗** → `OBJECT_HP` 可用，比較方向就是「HP `comparison` quantity」，**10 萬這種超 int16 的門檻照樣吃得下**。
- **E2 ✓、E1 E3 ✗** → int16 內的門檻也正常。（E1／C3 沒出現是期望值寫錯：U4 被加到 32040 而非 40，≤3 萬本就不成立。）
- **C1 ✓** → 跨命 OR 展開後「≤ 才封鎖」極性正確：低血本體 OR 高血備身 → 成立。
- **F1 ✓ 但 F2 也 ✓** → `MODIFY_VARIABLE_BY_ATTRIBUTE` **讀不到真血量**，變數路線作廢。
- **D1 ✓ D2 ✓** → **同一 tick 內，大 id 的封鎖器攔不住小 id 的效果**（被啟動的觸發在同一輪就依 id 順序評估）。
- U4 顯示 **32040/32040**，符合 int16 天花板 32767。

**東碼頭封鎖失效的根因＝D**：本體鏈是 `報價(3746)→確認(3747)→扣費(3750)`，而 `OBJECTS_IN_AREA` 只要
**任一隻**己方單位在區內就成立——帶馬／寵物走近時一隻踩報價線、另一隻已站在確認格，整條鏈在同一 tick 串完，
扣費（小 id）早於封鎖器（id 5677）執行。修法：**把扣費搬到新觸發 `X船費東`，讓封鎖器 `X船血東` 的 id 比它小**，
兩支由 `X船6` 同 tick 一起武裝（見 spec §三）。

## 結果（2026-08-30 使用者實測）

- ① **PASS**：`UNLOAD` 能把盟友乘客卸到指定岸格（原作 task-到-陸地格 在 DE 對盟友不卸）。
- ②a **PASS**／②b **FAIL**：駐軍中單位計入區域條件，但座標**凍結在登船那格**、不隨船移動。
  → 「海上偵測」不可行；替代：偵測「玩家物件出現在碼頭停船水域」＝已登船。
- ③ **只到 1 隻**：`TELEPORT_OBJECT` 區域選取一次只搬一隻 → 開 `spike_ferry2.py` 驗多隻寫法。
- v2（`spike_ferry2.py`）：A 單一效果 1 隻／B 同區域三效果三落點 3 隻／C `max_units_affected=10` 1 隻
  → 一效果一隻；`max_units_affected` 對傳送無效。
- v3（`spike_ferry3.py`）：同落點連傳只到 1 隻 → **落點被壓住＝傳送失敗、無事發生**。
  設計採「落點格迴圈 `TASK_OBJECT` 叫人走開、傳送迴圈重試」（見 `docs/superpowers/specs/2026-08-30-船夫搭船-design.md`）。
- v4（`spike_ferry4.py`，`SPIKE卸貨v4.aoe2scenario`，**2026-08-31 使用者實測 PASS**）：`船卸` 實戰形狀——一次性、區域選船、TIMER 8、派船時武裝。
  看三件事：① t20 派船時船上的人不被卸回（t25 不得出「✗」）；② 到東岸「★② 已下令」後乘客站上東岸；③ 回程再登船、t50 後回西岸。
  **教訓**：v4 第一版只鋪純水道（terrain 1），運輸船被 task 到對岸陸地格時走歪跑到左邊；使用者在編輯器補了水道外圈海灘＋
  兩端岸邊淺灘（terrain 2／4）後船就直直停靠。spike 地圖要有真實岸線過渡地形；本體地圖碼頭本來就是海灘接陸地，不受影響。
  `spike_ferry4.py` 已改成照該存檔鋪地形。
