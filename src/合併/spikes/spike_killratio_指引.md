# SPIKE擊殺計數 —— Kill Ratio 死亡回歸驗證（2026-08-30）

產檔：`python spikes/spike_killratio.py <template> <輸出>`，已部署 `SPIKE擊殺計數.aoe2scenario`。
單人→劇情，P1 遊玩。地圖中央：P1 騎士 1、P2 民兵 6（不還手）、遠處 P1 村民 1（t40 會被殺）。

## 背景

- 原作獎勵條件 `Accumulate Attribute 屬性44(Kill Ratio) ≥ 1`，KR＝擊殺 − 損失。
- 領獎後 `X升級` 觸發：建立 Joan → Kill → Remove，用一次「損失」把 KR 扣回 0（DE 中 Kill 仍計損失，故 Pikeman 正常）。
- **回歸**：英雄死亡＝損失 → 復活後 KR 為負 → 之後擊殺補不到 ≥1 → 獎勵停擺。原作死亡即結束所以無此問題。
- 修法候選：死亡時 `Modify Resource 屬性44 ADD +1`。本 spike 驗 DE 是否吃這個效果。

## 操作

1. 開局殺 1～2 隻民兵，觀察 [R]/[P]/[K]。
2. t40 出現 [D]（村民被殺）後，再殺 1 隻 → 看有無 [R]；再殺 1 隻。
3. t80 出現 [C]（KR ADD +2，未擊殺）→ 看是否立刻出現 1 行 [R]。

## 判讀

| 觀察 | 結論 |
|---|---|
| 每殺 1 隻恰出現 1 行 [R]，且 [P] 在第一殺出現 | KR 條件正常（陽性對照）＋ **SET 0 有效** |
| 第一殺後 [R] 每秒刷屏 | SET 無效 → 修法需改用原作 Kill 自己單位法 |
| [D] 後第 1 殺**無** [R]、第 2 殺有 | **死亡扣 KR 確認**（回歸根因成立） |
| [D] 後第 1 殺就有 [R] | 死亡不扣 KR → 根因另有他處，回報 |
| [C] 後未擊殺即出現恰 1 行 [R] | **ADD 有效** → 修法：死亡監視加 ADD +1 |
| [C] 後無反應 | Modify Resource 對屬性 44 無效 → 改用「復活時建立 P7 單位讓玩家秒殺」等替代 |
| [K1]～[K4] 隨擊殺遞增、不受 [D] 影響 | 屬性 20 為純擊殺數（備用方案） |
