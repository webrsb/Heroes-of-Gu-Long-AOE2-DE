# 01b — `operation` 三種值並排：−1 到底是 ADD 還是 SET  【P0】

**重現檔**：`ZZ_test01b_負血重測`　**狀態**：✅ **已完成**

## 問題

`01` 因為漏設 `operation`，parser 預設填了 ADD(2)，導致
`A + (65536 − A)` 互相抵銷回基礎血量 45，**沒有真正產生負血**，測試前提失效。

本體 **790 個** `Change Object HP` 效果全部使用 `operation = -1`。
AoC 沒有這個欄位，所以 −1 的語意是整個血量分析的地基：
若是 SET，最大血量會被真的設成回繞負值；若是 ADD，則只是累加。

## 測試設計

三條並排，唯一差異是 `operation`：

| lane | `operation` | 說明 |
|---|---|---|
| L1 | **−1** | 本體實際使用的值 |
| L2 | 1 = SET | 若 −1 等於 SET，L1 應與此相同 |
| L3 | 2 = ADD | 校準基準 |

## 結果（實機）

| lane | operation | 存活 | 血量 | 判定 |
|---|---|---|---|---|
| L1 | **−1** | 存活 | 45 | **與 ADD 相同** |
| L2 | 1 = SET | **死亡** | — | 真的設成回繞負值 → DE 殺死單位 |
| L3 | 2 = ADD | 存活 | 45 | 基準 |

**第二個佐證**：在同一檔手動追加一個 `Change Object HP` 參數 1000 的效果，
血量變成 **1045**（= 45 + 1000）而不是 1000。

**第三個佐證**：把測試檔在 DE 編輯器開啟再存檔，`operation = -1` 被寫回成 **2**。
DE 編輯器主動把 −1 正規化成 ADD。

## 結論

**`operation = -1` 在 DE 等同 ADD（相加）。**

AoC 同樣是 ADD，由 `NAKUZ` 文本自身反證：Q68 第三步 `A − 32767` 標註「還原」，
只有相加才能還原；Q61 的 `65536 − 單位上限值` 相加後回繞為 0，正是「雙0血」。

→ **本體 790 個效果沒有語意落差，這一項不需修改。**
→ 但這推翻了規則書早期所有以「設定」為前提的血量推論（見規則書第六部分）。

規則書：§1.2c
