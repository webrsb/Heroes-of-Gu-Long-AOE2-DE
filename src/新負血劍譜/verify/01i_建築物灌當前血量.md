# 01i — 建築物能不能像單位那樣灌當前血量  【P0】

**重現檔**：`ZZ_test01i_建築物灌當前血量`　**狀態**：✅ **已完成**

## 問題

單位可以「爆血」（`毀僧聖僧 155,204,672/70`）。
`亡魂之堡` 在舊版是 `6000300/300`，同一套手法用在建築物上。
DE 的建築物吃不吃這一套？

`01f` 當時的結論是「建築物完全不吃 `Damage Object` 負值」，
但那次城堡是**滿血**狀態，補不上去所以看不出差別 —— 測試設計有缺陷。
本檔先把城堡扣掉 1000 血（`3800/4800`）再施加各種做法。

## 結果（實機）

| lane | 做法 | 血量 | 解讀 |
|---|---|---|---|
| I1 | `Heal Object` 6,000,000 | **4800/4800** | 補到**滿**，不超過 |
| I2 | `Damage Object` −6,000,000（**區域** targeting） | **4800/4800** | **有生效**，補到滿 |
| I3 | `Damage Object` −6,000,000（**類型** targeting） | **4800/4800** | **有生效**，補到滿 |
| I4 | `Modify Attribute` → `REGENERATION_RATE` +10000 | 3800/4800 | 無變化 |
| I5 | `Change Object HP` +27,967 | **25940/32767** | 天花板 32767 確認 |
| I6 | 未施加（基準） | 3800/4800 | — |

## 結論

```
單位   ：當前血量可以遠超最大血量      （155,204,672 / 70；1045 / 45）
建築物 ：當前血量被夾在最大血量以內    （怎麼灌都只到 4800 / 4800）
```

**推翻 `01f` 的結論**：建築物**有**吃 `Damage Object` 負值，
真正的限制是它會把當前血量**夾在最大值**。

I5 再次驗證等比縮放模型：`3800 × 32767/4800 = 25940.7` → 實測 **25940**。

→ 當時的推論是「`亡魂之堡` 有效血量上限就是 32767」。
　 這個推論後來被 `01n` 的**雙0血**推翻（max = 0 時夾限不生效）。
