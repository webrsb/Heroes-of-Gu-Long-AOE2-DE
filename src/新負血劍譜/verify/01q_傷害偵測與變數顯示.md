# 01q — 雙0血下的傷害偵測與變數顯示  【P0】

**重現檔**：`ZZ_test01q_傷害偵測與變數顯示`　**狀態**：✅ **已完成**

## 三個問題

| # | 問題 | 為何要問 |
|---|---|---|
| Q1 | 雙0血狀態下 `Object HP` 條件讀不讀得到當前血量？ | `01p` 證實變數那條路封閉，這是唯一剩下的途徑 |
| Q2 | `<變數名>` 能不能長駐顯示在畫面上？ | 社群說可以，本專案未驗 |
| Q3 | `Kill Object` 能不能殺死雙0血建築？ | 勝利鏈需要 `DESTROY_OBJECT` 成立 |

讀數全部走**聊天訊息**，避免 `01n` / `01o` 改名互相覆寫的問題。

## 結果（實機）

**Q1 ✅** 聊天欄依序回報血量門檻：`5,900,000` → `5,500,000` → …
→ `Object HP` 條件吃 `unit_object`，是**實例層級**，
　 且在雙0血（最大血量 0）狀態下**讀得到**當前血量。

**Q2 部分成立**：
| 語法 | 結果 |
|---|---|
| `<變數名>` | ✅ **有效**（畫面顯示「階段=3」） |
| `<!stone storage>` | ❌ **無效**，顯示字面文字 |

**Q3 ✅** `Kill Object` 能殺死雙0血建築，`DESTROY_OBJECT` 成立。

## 結論

三件事湊齊，`亡魂之堡` 的完整修法成立：

```
雙0血               -> 建築物可持有 600 萬血且不死          01n
Object HP 條件      -> 實例層級，讀得到當前血量             01q Q1
<變數名>            -> 把數字長駐顯示在畫面上               01q Q2
Kill Object         -> 血量歸零時擊殺，勝利鏈照跑           01q Q3
```

→ 血條的具體做法（門檻階梯、百分比、排版、開關）見 `01r` / `01s` / `01t` / `01u`。
