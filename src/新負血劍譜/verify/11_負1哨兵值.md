# 11 — `-1` 是不是被當成「未設定」的哨兵值

**狀態**：✅ **已測・結論分歧** —— 進貢的 `-1` 無效，傷害的 `-1` 有效。本體皆不受影響

## 起因

`ZZ_test07e` 用「每個有效 ID 給 +1 石頭」當計數器（`Tribute quantity = -1`），
結果石頭停在 0。使用者指出 **`-1` 在觸發器欄位裡就是「未設定」的哨兵值**。

這不只是測試檔的 bug。靜態掃描本體：

```
Tribute       quantity = -1     0 處   （最小是 -2）
Damage Object quantity = -1    50 處   ← 作者意圖「回血 1 點」
```

## 測試設計（`ZZ_test11`）

兩條線，各自帶 `-10` 對照組：

| | 動作 | 有效 | 無效 |
|---|---|---|---|
| A 騎士 | 先扣 50 血，再 `Damage -1` ×5 | 血 55 | 血 50 |
| B 騎士（對照） | 先扣 50 血，再 `Damage -10` ×1 | 血 60 | — |
| 石頭 | `Tribute -1` ×5 | 5 | 0 |
| 木材（對照） | `Tribute -10` ×1 | 10 | — |

## 結果

**2026-08-29 實測。**

| 項目 | 實測 | 判定 |
|---|---|---|
| A 騎士 `Damage -1` ×5 | **55/100** | ✅ **有效** |
| B 騎士 `Damage -10` ×1 | 60/100 | ✅ 對照成立 |
| 石頭 `Tribute -1` ×5 | **0** | ❌ **無效** |
| 木材 `Tribute -10` ×1 | 10 | ✅ 對照成立 |

### 結論：`-1` 只在「進貢」欄位被當成未設定

兩個效果的 quantity 欄位在檔案格式上是同一個位置，
但引擎的處理不同：

- **`Damage Object` 照常把 `-1` 當成「回血 1 點」** —— 數值沒有被特判
- **`Tribute` 把 `-1` 視為未設定，整個效果不執行** —— 不是夾成 0，是不執行

### 對本體的影響：無

| 寫法 | 本體用量 | 結果 |
|---|---|---|
| `Tribute -1` | **0 處** | 沒踩到 |
| `Damage -1` | 50 處 | **有效，照常回血 1 點** |

→ **兩者都不必改。**

### 小額邊界（`ZZ_test11b`）—— 已補驗

四種資源各施加一次小額負進貢：

| 金額 | 資源 | 實測 | |
|---|---|---|---|
| **−1** | 食物 | **0** | ❌ 無效 |
| **−2** | 木材 | **2** | ✅ 有效　★本體 48 處用這個值★ |
| **−3** | 石頭 | **3** | ✅ 有效 |
| **−5** | 黃金 | **5** | ✅ 有效（09 已知） |

**邊界只有 `-1` 一個點。** 不是「小額被夾掉」，而是 `-1` 這個特定值被
`Tribute` 效果視為未設定。`-2` 起一切正常。

→ 本體 **48 個 `Tribute -2` 安全**，加上 0 個 `Tribute -1`，
　整個負進貢家族確認無風險。

### 連帶修正：`Own Fewer Objects` 的語意

07e 45 個 ID 全部誤報 `[無效]`，原因是我把
`Own Fewer Objects` 的 `quantity` 當成「小於 N」。

**它其實是「擁有數 ≤ N」** —— 本體用它時填 `quantity = 0`
（例如 `飛鵬幫先鋒`、`飛鵬幫戰將`），若語意是「小於 0」則永遠不成立，
可見必為「≤ N」。我填 1，於是「正好擁有 1 個」也算成立，45 個全中。

→ `ZZ_test07e` 的 `[無效]` 清單**整份作廢**，
　改用 `ZZ_test07g`（`quantity = 0`）重驗。
