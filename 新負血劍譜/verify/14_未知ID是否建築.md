# 14 — 未知 const 是不是「建築物」（會不會被夾血量）

**狀態**：✅ **已測** —— 未知 const 之中**只有 `208` 是建築**，需要雙 0 血

## 起因：盤點有破口

`audit_buildings.py` 用 parser 的 `BuildingInfo` 判斷是不是建築，
**未知 ID 一律被跳過**。而本體剛好有一批未知 const 正在被灌血：

| const | 數量 | ΔmaxHP | 灌血 | 備註 |
|---|---|---|---|---|
| **208** | 1 | **+79640** | **−1,000,880** | ref 31245 (0.5,4.5)，`亡魂之堡` (3,5) 正後方 2.5 格 |
| 37 | 12 | +4890 | −200,000 ×6 | 地圖上緣「弟子」那批 |
| 94 | 3 | | −460,796（30319） | 牆區 |
| 573 | 1 | +55 | −1,000 | |
| 436 | 1 | +925 | 0 | 沉船 |

使用者指出「`亡魂之堡` 後面那個也是要打倒的建築物」——
靜態資料證實 `ref 31245` 確實是打擊目標：

```
[4421] 賓名          Change HP  +9400
[4679] 觸發事件4833   Change HP  +12000
[4755] 觸發事件4913   Change HP  +55537 -> 再 +9999   ← 規則書早記的「三明治」
[5039] 塔魂          Change HP  -7296              ← 效果名稱就叫「塔魂」
[4607] 嬴 / [4677]   DESTROY_OBJECT 條件            ← 要打倒它才會推進
```

DE **只夾建築物**的當前血量（單位不夾，`ZZ_test01` 系列已驗證），
所以「是不是建築」直接決定要不要一起做雙 0 血。靜態判斷不了，只能實測。

## 測試設計（`ZZ_test14`）

七個物件並排，統一 `Change HP +1000` → `Damage -50000`，
再用 `Object HP` 門檻 20000 判定當前血量有沒有真的超過上限。

對照組：`CASTLE(82)` 必須「已夾」、`KNIGHT(38)` 必須「未夾」。

## 結果

**2026-08-29 實測。七個物件都成功擺放（`[存在]` 七行全到）。**

| const | 標籤 | 結果 | 判定 |
|---|---|---|---|
| 82 | 對照 CASTLE | **已夾**（血量 < 20000） | ✅ 陽性對照成立 |
| 38 | 對照 KNIGHT | **未夾**（血量 > 20000） | ✅ 陰性對照成立 |
| **208** | **亡魂之堡後面那座** | **已夾** | ❌ **建築行為，要雙 0 血** |
| 37 | 上緣「弟子」那批 | 未夾 | ✅ 不是建築 |
| 94 | 牆區 30319 同型 | 未夾 | ✅ 不是建築 |
| 573 | | 未夾 | ✅ 不是建築 |
| 436 | 沉船 | 未夾 | ✅ 不是建築 |

兩個對照組都正確 → 測試有效。

## 結論

**未知 const 之中只有 `208` 會被夾。**

- `ref 31245`（const 208）加入雙 0 血清單 → 總數 **13 個**
- const 37 的 12 個、const 94 的 3 個、573、436 全部是單位行為，
  灌血照常運作，**原樣遷移**

那批被灌 −200,000 的「弟子」原本看起來最可疑，實測證明無害。

## 順帶確認

`ZZ_test07g` 說 208 / 37 / 94 / 573 都能 `Create Object`；
本測試進一步證明它們也能**擺放**且能被 `Object HP` 條件讀取。
只有 436 的「無外觀」是這批未知 ID 唯一的實質缺陷。
