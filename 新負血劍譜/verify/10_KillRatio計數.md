# 10 — `Kill Ratio` 當擊殺計數，在 DE 還有效嗎  【P1】

**狀態**：✅ **已測・計數正常** —— 268 處不必改。FAQ 的重置技巧在 DE 失效，但本體使用 0 次

## 問題

AoKH FAQ 的每殺一隻給獎勵：

> ```
> Condition0: Accumulate Attribute (1 Kill Ratio: Player 1)
> Effect0: Tribute (10 Gold: GAIA -> Player 1)
> Effect1: Create Object - any unit at hidden location
> Effect2: Remove Object - unit just created
> Trigger looping: Yes. Resets kill ratio after each reward.
> ```

本體 **268 處**使用 `Kill Ratio`（屬性 44）。
`Kill Ratio = 擊殺數 − 損失數`。

`Accumulate Attribute` 條件的屬性分布：

| 屬性 | 數量 | 意義 |
|---|---|---|
| 2 | 620 | 石頭（經驗值） |
| **44** | **268** | **Kill Ratio** |
| 1 | 216 | 木材（技能點） |
| 3 | 107 | 黃金（銀兩） |
| 0 | 6 | 食物 |
| 43 | 1 | Razings |

## 三個要驗的問題

| # | 問題 |
|---|---|
| Q1 | 條件在 DE 是否仍成立？ |
| Q2 | 是否會隨擊殺數累加（>=1、>=2、>=3 依序成立）？ |
| Q3 | FAQ 的「建立+移除物件」重置法在 DE 還需要／還有效嗎？ |

## 測試設計

P1 騎士自動去殺 5 個 P2 村民（已設原地防守，不會逃）。

- 五個非循環觸發器，門檻 `Kill Ratio >= 1~5`，各自回報
- 一個**循環**觸發器完全照 FAQ 寫法：`Kill Ratio >= 1` → 黃金 +10
  → 建立綿羊 → 移除綿羊
- 用黃金累積量反推重置是否有效（10 / 30 / 50 三個門檻）

## 判讀

| 觀察 | 結論 |
|---|---|
| 依序出現「Kill Ratio 已達 1..5」 | 條件正常且會累加 |
| 完全不出現 | **268 處全部失效** |
| 黃金累加到 30 以上 | FAQ 的重置寫法在 DE 仍有效 |
| 黃金停在 10 | 重置無效（計數不歸零，只給一次獎） |

⚠️ 本檔的黃金是用**負進貢**給的，所以同時是 **09 的交叉驗證** ——
若 09 失效，本檔的黃金門檻也不會回報，判讀時要先確認 09 的結果。

## 結果

**2026-08-29 實測（`ZZ_test10`）。**

```
[結果] Kill Ratio 已達 1        （第 1 個村民被殺時）
[結果] 黃金 >= 10（第 1 次獎勵）
[結果] 黃金 >= 50（5 次全給）    ← 20 秒標記之前
--- 已過 20 秒 ---
[結果] Kill Ratio 已達 2        （第 2 個村民被殺時）
--- 已過 40 秒 ---
[Q3] 重置寫法執行一次（黃金 +10）
最終黃金 = 520
```

### 一、`Kill Ratio`（屬性 44）計數正常 ✅

門檻 1 與 2 各自準確跟著一次擊殺出現，時間點與擊殺一致。
（3/4/5 未出現是騎士在觀察窗內只殺了 2 個村民，非條件失效。）

→ **本體 268 處 Kill Ratio 條件不必改。**

### 二、FAQ 的「重置」技巧在 DE 失效 ❌

FAQ 教的做法：領完獎後生一隻羊再 `Remove Object` 掉，
用「損失 +1」把 Kill Ratio 扣回去，讓同一門檻能重複觸發。

**實測：`Remove Object` 刪掉自己的單位不計入損失。**
Kill Ratio 扣不回去，循環觸發器持續發獎 —— 只有 2 次擊殺，黃金卻累積到 **520**
（= 52 次發獎）。時序也吻合：`黃金 >= 50` 在 20 秒標記前就達成，
遠早於第 2 次擊殺。

### 三、對本體的影響：無

靜態掃描本體 268 個 Kill Ratio 條件：

```
分布於 268 個觸發器
  一次性觸發器 250      <- 打完不再判定
  循環觸發器    18
  循環 ∧ Create+Remove（FAQ 重置寫法）  0     <- 本體從未使用
```

18 個循環觸發器逐一檢視，全部安全：

| 觸發器 | 效果 | 為何安全 |
|---|---|---|
| `1殺`~`6殺` | `Activate Trigger` | 重複啟動同一觸發器是冪等的，無副作用 |
| `1船4`~`6船4` | `Activate Trigger` | 同上 |
| `1木2`~`6木4` | 送木材 2 點 → **`Deactivate Trigger` 指向自己** | 作者用觸發器開關收尾，不依賴 Kill Ratio 扣減 |

→ **重置失效不影響本體。** 這是寫**新**觸發器時要避開的坑，
　不是遷移障礙。

### 附記：這是 DE 的行為改變

AoC 時代 `Remove Object` 自己的單位會計入損失（FAQ 即以此為前提），
DE 已不再如此。日後若需要「同一門檻重複發獎」，
正解是**觸發器開關**（本體 `1木2` 的寫法），不是 Kill Ratio 扣減。

規則書：§2.8a ③
