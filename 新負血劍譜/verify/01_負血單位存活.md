聊天欄：空白。
追加手動測試：另加一個 `Change Object HP` 參數 1000 → 血量變成 **1045**。

### 測試檔的瑕疵

`change_object_hp` 沒指定 `operation`，AoE2ScenarioParser 預設寫入 **2 = ADD（相加）**。
於是兩步變成相加而非設定：

```
45 (Man-at-Arms 基礎血量)
 + A
 + (65536 - A)
 = 65581      對任何 A 都一樣
65581 mod 65536 = 45
```

四條 lane 的 A 值不同卻全部顯示 45，正是這個算術的結果。**測試沒有產生負血狀態**，
所以第一輪**無法回答**「負血單位是否存活」。

### 但確定了兩件事

1. **DE 確實對 `Change Object HP` 執行 int16 回繞（mod 65536）** ✅ 等級 A
   證據：中途值 65581 回繞成 45，四隻一致。規則 1.1 的 int16 模型在 DE 側成立。
2. **該 operation 的語意是 ADD** ✅ 等級 A
   證據：手動追加參數 1000 → 血量 1045（= 45 + 1000），不是 1000。

### 浮現的新問題（比原問題更關鍵）

本體戰役 **790 個 `Change Object HP` 的 operation 全部是 `-1`**，
而 `-1` 不是合法枚舉值（SET=1, ADD=2, SUBTRACT=3, MULTIPLY=4, DIVIDE=5）。

AoC 沒有這個欄位、語意固定為「設定」，所以 -1 理論上應被當成 SET——但尚未實測。
**這是所有血量推論的共同前提**，見規則書 §5.4。

## 判讀

### 主問題：`op=-1` 到底是什麼語意

| L1 (op=-1) 顯示 | 結論 | 影響 |
|---|---|---|
| **45** | -1 被當成 ADD | 🔴 本體 790 個效果的實際行為全與作者原意不同，需全面重估 |
| **負值 / 異常** 且單位存活 | -1 被當成 SET，且負血可用 | ✅ 本體寫法照原意運作，負血機制安全 |
| 單位**消失** | -1 被當成 SET，但 DE 殺死負血單位 | 🔴 8 個負血效果需改用替代方案 |
| 12038 或 53498 | -1 有第三種語意 | 記錄實際值，需再分析 |

### 交叉校準

- `L3 op=ADD` **必須**顯示 45。若不是，測試環境有問題，其他 lane 的結果不可信。
- `對照組` **必須**顯示 45。
- 若 `L1` 與 `L2` 顯示相同 → 證實 -1 等同 SET。
- 若 `L1` 與 `L3` 顯示相同 → 證實 -1 等同 ADD。

## 若確認 DE 會殺死負血單位 — 替代方案

1. **`Modify Attribute` 屬性 129 `Invulnerability Level`**
   UGC 指南：`> 0` = 基礎血量倍率，`< 0` = **固定血量模式**。DE 原生機制。
2. **最大血量設 32767 + 負傷害灌當前血量**
   本體已有 10 處這樣用，且與作者其他 638 處手法一致。

## 結果（回填 2026-08-29）

### 這一輪的瑕疵

產生器漏設 `operation`，parser 預設填了 **ADD(2)**，於是
`A + (65536 − A)` 互相抵銷回基礎血量 45 —— **根本沒有產生負血**。
測試前提失效，負血存活與否本輪無法回答。

### 但取得了兩項確定結論

**① `operation` 的語意 = ADD**

在同一測試檔手動追加一個 `Change Object HP` 參數 **1000** 的效果，
血量變成 **1045**（= 45 + 1000），而不是 1000。

> 使用者更正：「更正，不是 1000 是 1045」—— 這句話定了整份血量分析的地基。

**② 單位在 DE 沒有因為這些效果而死亡**（雖然本輪沒真的翻負）
