# 01n — 雙0血：`NAKUZ` Q61 完整三步套在建築物上  【P0・關鍵突破】

**重現檔**：`ZZ_test01n_雙0血`　**狀態**：✅ **已完成 —— 這是整個血量問題的解答**

## 問題

`01g` / `01i` / `01j` 一路排除，當時的結論是
「DE 沒有任何方法能讓建築物的有效血量突破 32767」。

但 `NAKUZ` Q61 的完整結構從未測過：

```
效果：改變目標生命值｜參數：65536 − 單位上限值
效果：摧毀目標      ｜參數：2147483648
效果：摧毀目標      ｜參數：2147483648
```

解讀：
- 第一步 ADD(65536 − A) → 最大血量 = A + 65536 − A = 65536 → int16 = **0**
- 後兩步 `2147483648 = 2³¹`，當 int32 讀為 **−2147483648**
  → `Damage Object` 負值 = 治療 21 億，把當前血量灌爆

**先前為何漏掉**：`01c` 的 C2 只做了第一步（max 變 0），沒做後兩步灌血，
所以當前血量也跟著變 0 而死亡 —— 用不完整的結構「證明」了它不可行。

## 結論

**雙0血（最大血量 0 + 當前血量極大）讓建築物在 DE 也能持有 600 萬血量並保持可受傷。**

關鍵在於：**建築物的當前血量夾限只在最大血量 > 0 時生效**。
最大血量為 0 時夾限不作用，當前血量可以任意大。

死亡判定只看當前血量 ≤ 0，所以它會持續掉血、可被偵測、最後可被擊殺 ——
正是 `亡魂之堡` 需要的行為。

→ 推翻 §5.5.1 的「無法突破 32767」與 §5.5.2 的全部選項。
→ 本檔的兩個缺陷（灌 42.9 億超出 `Object HP` 條件的 int32 上限、
　 30 秒存活標記覆寫 20 秒血量探測）由 `01o` / `01q` 改用 600 萬真實值解決。
