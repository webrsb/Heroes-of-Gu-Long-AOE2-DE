## 已完全確立的模型（等級 A）

```
最終最大血量 = 單位基礎血量 + int16( Σ 所有已執行的 Change Object HP 參數 )
```

- `operation = -1` 等同 **ADD（相加）**（`ZZ_test01b`：L1 與 L3 結果相同）
- 用 **SET** 設成回繞負值 → **死亡**（`ZZ_test01b`：L2 死亡）
- **最終血量 ≤ 0 → 死亡**，界線精確在 0（`ZZ_test01c`：C1 剩 1 血存活、C2 正好 0 血死亡）
- **回繞產生的負值與直接給的負值行為完全相同**（`ZZ_test01c`：C4 與 C6 皆死亡）
- AoC 亦為 ADD（nakuz Q61「雙0血」與 Q68「還原」步驟反證）
- DE 編輯器存檔時會把 `-1` 正規化成 `2 (ADD)`

## 若有坐騎會死 — 修法

現在模型完全確立，修法很直接：**調整 `馬血` 的參數，讓淨增量落在安全值**。

例如 Tamerlane 淨增量 −250，若其基礎血量為 200，要讓它剩 100 血：
```
目標淨增量 = 100 - 200 = -100
現行 馬血 參數 53818  ->  改為 53818 + 150 = 53968
```
（因為 `11468 + 53968 = 65436`，`65436 mod 65536 = 65436`，
　int16 = −100 → 200 − 100 = 100）

我可以用 AoE2ScenarioParser 依你想要的目標血量批次算出新參數。

### 這推翻了先前的判斷

原本以為 `馬血` 的 ~53000 是 HP 溢位 bug、DE 會秒死。實際上：

**`馬血` 是刻意的血量正規化。** 六隻坐騎基礎血量各不相同
（Elite Mameluke 80、Henry V 240…），作者用 `65536 − 基礎血量 + 100`
這類寫法把每一隻**校正到恰好 100 左右**，讓坐騎不論品種血量一致。

累加後回繞的結果是**正值 95～100**，不是負值。實作完全正確。
