# 01e — 單位能不能處在「負最大血量」而存活  【P0】

**狀態**：✅ **已完成 —— 負最大血量是可用狀態**

**重現檔**：`ZZ_test01e_先灌血再翻負`　**耗時**：約 20 秒

## 要回答什麼

實際遊玩中那隻王（`ref 44239` Harald Hardrada）**血量很高但顯示負值、而且活著**。
但 `ZZ_test01c` 的單位一旦最大血量 ≤ 0 就死。

唯一差別：**那隻王在翻負之前，先吃了 952,535 點負傷害治療。**

## 已知的關鍵前提（`ZZ_test01g` G7 實測，等級 A）

步兵吃 `Damage Object −1000` 後顯示 **`1045/45`**。

→ **當前血量（1045）與最大血量（45）是各自獨立的欄位**，顯示格式為「當前 / 最大」。
→ 所以「先灌血再翻負」理論上會得到「當前血量仍為正、最大血量為負」的存活狀態。
→ 這正是那隻王的狀態。本測試就是要證實它。

## 結論

**順序決定生死，負最大血量本身不致命。**

```
先治療、後翻負  ->  等比縮放把當前血量也拖成負值  ->  死亡
先翻負、後治療  ->  負傷害把當前血量推回正值      ->  存活（最大血量停在 -205）
```

E5 是關鍵證據：**單位可以長期停在「最大血量為負」的狀態而存活**，
提示框照樣顯示 `−205`。這正是本戰役「負血」機制的運作方式，
也解釋了王「血量很高但顯示負值」的現象。

→ **AoC 的負血是可用狀態，DE 行為相同，這一項不需修改。**
→ 先前「舊版也會有事，一直是壞的」的判斷已撤回。
