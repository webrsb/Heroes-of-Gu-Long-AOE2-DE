# 02b — `Change Object Attack` 的實際數值上限  【P0】

**狀態**：⚠️ **已完成，但結論被 `02d` 推翻（UI 數字不可信）**

**重現檔**：`ZZ_test02b_攻擊力上限`　**耗時**：約 40 秒
**取代**：`ZZ_test02`（舊版靶單位會亂跑反擊，且靠戰鬥推算不可靠）

## 要回答什麼

| 來源 | 說法 |
|---|---|
| UGC 指南 | 數值上限 **255**，更高要「用多個效果或加法／乘法運算」 |
| AoE2ScenarioParser（trigger 2.5） | class 與 amount 各 2 bytes，上限 **65535** |

**473 個效果的修法完全取決於答案**，本體最大需求 **30000**：

- 上限 65535 → 直接寫 `class=0, amount=原值`，**可批次修復**
- 上限 255 → 得改用 `Modify Attribute` 或拆成上百個效果，工程量與風險大增

## 這版改良了兩件事

**① 主判讀改成「直接讀攻擊力數字」，不靠戰鬥推算。**

依據是舊版實機畫面 `速不臺` 顯示 **`12+31001`** —— 證明遊戲會把攻擊加成
顯示成「基礎+加成」。直接讀數字比數幾下打死可靠得多。

**② 交叉驗證的靶單位已 `Freeze Object` 凍結**，不會亂跑或反擊。

## 為什麼這題最重要

`[4709] 刀3` 同時做兩件事：給 **+21000 攻擊力**、啟動 **6000/秒扣血**。
DE 已把那個攻擊力切成 **+8**。

→ **現在在 DE 買神兵，是拿全部代價、換不到任何好處。** 這一關會直接卡死。
→ 修好攻擊力才能恢復「爆血換攻擊力」這個核心玩法。

## 結果（回填 2026-08-29）

### 取得的確定結論

**沒有 255 上限。** `UGC` 指南所稱「quantity 上限 255」與實測不符 ——
`class=0` 帶 30000 可一擊秒殺 2045 血的靶（`02d` E6 再次確認）。

### 被推翻的結論

本檔依**提示框**數字寫成，同一個效果（`class=0, amount=100`）
提示框顯示 **「近戰 −94」**，於是當時的結論是「`class=0` 是減不是加」。

`02c` 對同一份資料看**面板**，顯示的是 **`6+100`** —— 兩個 UI 互相矛盾。

`02d` 改用**實際戰鬥傷害**量測，證實 `class=0, amount=100` 造成的傷害
與 `class=4, amount=100` **完全相同**（都是攻擊力 106）：

> **提示框的 `−94` 是顯示假象，不是實際攻擊力。`class=0` 確實是「加」。**

## 結論

- ✅ 沒有 255 上限 —— 這一項成立，是修法可行的前提
- ❌ 「class=0 是減」**作廢**（規則書舊 §3.3b 已標註作廢）
- 📌 教訓：**不要相信 UI 數字**，攻擊力一律以實際傷害量測為準
