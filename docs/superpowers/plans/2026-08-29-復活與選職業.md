# 復活與選職業系統 實作計畫

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在古龍921_合併加入遊戲內選職業（6職業×6玩家位全矩陣）與每職業 10 條命的復活系統，並修復五個 DE 圖形佚失 const。

**Architecture:** 全部改動經合併流水線（單一入口 build.py，步驟 auto-registry）。接線走方案二：效果 ref 清單追加備身＋玩家欄中性化；條件 OR 展開跨命；玩家定址觸發做家族閉包後 ×6 玩家位矩陣，選角時啟動配對變體。藏兵艙＝隱形物件(1291)預駐＋死亡時「先換家再移除容器」彈出。

**Tech Stack:** Python + AoE2ScenarioParser 0.8.4、pytest、merge_spec.yaml 裁決制（缺裁決=BuildError）。

**Spec:** `docs/superpowers/specs/2026-08-29-復活與選職業-design.md`（v5，使用者已核可）

## Global Constraints（鐵律）

- 絕不覆寫任何來源檔；產物一律 `out/古龍921_合併.aoe2scenario`
- 絕不從 DE 編輯器存檔；所有寫入走 AoE2ScenarioParser，且只有 `core/scenario_io.py::write_out()` 呼叫 `write_to_file`
- 寫檔前 `trigger_manager.legacy_execution_order = True`
- 測試走 單人→劇情；每個測試檔必須帶陽性對照組
- merge_spec.yaml 是圈選與裁決唯一權威；模糊情境一律 raise BuildError，不默默裁定
- 一次建置＝一個 commit；雙軌 log 固定檔名；文件溝通全繁中
- 觸發新增一律 append（不得移動既有 trigger_id）
- 新步驟遵循 `steps/__init__.py::get_steps()` auto-registry（`sNN_*.py` 內 `STEP`），無須改 build.py
