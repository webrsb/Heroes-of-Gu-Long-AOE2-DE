# 狀態頭頂字幕（設計）

2026-09-02。使用者需求：**角色狀態用 caption 顯示在頭上（同一開始的職業標示手法），死亡重生的替身不得顯示**。
裁決（2026-09-02 三問定案）：**狀態牌全部照搬**（含奪命神弓等特殊字樣）；頭頂文字**去「狀態」二字、
「生命值」改「精力」**（配合遊戲名詞）；解除（寫回「正常」）時**清空頭頂文字**。

資料基礎：合併檔 `out/古龍921_合併.aoe2scenario` 全量觸發權威盤點（parser 掃描，非 dump 逐行——
dump 訊息含換行會漏）；引擎事實引用通用指南與 verify 既有實測，本設計**不依賴任何未實測語意**。

## 一、原作狀態系統（盤點結果）

- 狀態顯示走**每職業一顆「狀態牌」物件**，以 `Change Object Name`（效果 26）改名呈現。
  牌 ref → 職業：**{20501:1, 20502:2, 20504:3, 20503:4, 20505:5, 20506:6}**——3/4 對調是原作擺位特性，
  已驗證全狀態家族一致（X毒/X震/X內 同一對應）；六座位變體**不改寫牌 ref**（`1毒◇位2` 仍寫 20501），
  即牌跟職業走，可當全域鍵。
- 全檔狀態牌寫入 **768 個效果**（124×4＋130＋142），sel 全部恰為單一牌 ref、無混搭（已驗證）。
- 相異文字 14 種（strip 後歸併；`20502` 有一筆帶 CRLF 的「正常」變體）。
- 馬形態有**專屬設定器**：`X毒3`／`X內2`／`X震2` 六職業齊備，條件 `BRING 毒物/內傷物/震懾物 next=mount_ref`
  ——中毒、內傷、震懾三態是原作明定「打得到騎馬者」的狀態。

## 二、機制：新建置步驟 s51（純掃描附掛）

字串排序自動落位 s50（caption 血條）之後、s80 之前。**0 支新觸發**，全部是既有觸發尾端附掛效果。

1. **掛字規則**：掃全檔（原觸發＋變體一體適用），凡效果為 `Change Object Name` 且 sel 恰為一顆狀態牌 ref，
   就在**同一支觸發**尾端補一個 `Change Object Caption`（效果 88）：
   - 目標 sel＝該職業**全部命 ref**（`life_refs`，seat 無關）。死 ref 落空無害、駐容器備身看不到字。
   - **若該觸發自身條件（含 OR 節點）引用該職業 mount_ref**（即 X毒3/X內2/X震2 家族）：sel 額外加 mount_ref
     → 騎預置馬騎期間三態照常顯示。
   - **清除類寫入**（映射值為清除）：sel＝命 ref＋mount_ref。清字無害，順帶自癒「上馬前毒物晃到伯樂馬旁寫牌」
     的原作繼承邊角。
   - 所有 caption 效果 `source_player=-1`——**sel 有值時 sp 不過濾**（通用指南 §7.1，2026-09-01
     `spike_spfilter` 實測結案），不依賴不存在的所有權過濾語意。
2. **牌 ref→職業映射建置期推導驗證**：從原觸發 `X毒`（X=1..6）的條件命 ref 與 E1 牌 ref 重新推導對應，
   與上表對不上即 BuildError 中止（不寫死盲信）。
3. **裁決表**（`merge_spec.yaml` → `params.status_caption.texts`）：key＝原文 strip 後字串，

   連續空白壓一格」推得，日後補新條目沿同規則）。**掃描遇到表外文字即 BuildError，缺裁決不默默補**：

## 三、替身保證（核心限制的落實）

caption 綁物件、換主人不消失（s39 選角後手動清職業名即此因）。兩道清字 hook 保證「新身體出場必乾淨」：

1. **重生清字**：`重生{職業}位{座位}命{L}` timer 觸發（6×6×(lives−1)＝**72 支**，lives=3 現值，
   自 `ctx.notes['revive_out']['chains']['timer']` 取得）各補 caption `' '` on 部署 ref `life[cid][L]`。
   最後一命死亡退場無新身體，不處理。
2. **上馬清字**：`X馬3◇位S◇命L` 拷貝（6×6×lives＝**108 支**）各補 caption `' '` on `mount_refs[cid]`，
   拿馬那刻保證頭上乾淨。**需 s39 在 `notes['revive_out']` 增列 `mount_copies`**（`rebuild_mount` 的
   `out.copies`；僅 notes 資料、不改建置產物）。

依使用者裁決，重生後的新身體**即使機制上狀態仍在**（如毒 DoT 迴圈未解）也不顯示狀態字，直到下一次狀態牌寫入。

## 四、騎馬流程相容性（§七之三 v4，已全數實證）

- 上馬＝移除步行本體＋預置馬騎（`mount_refs`：{1:26109, 2:26186, 3:26136, 4:26139, 5:26138, 6:26110}）
  轉讓給玩家＋**剩餘備身 REPLACE 成馬 const**＋永久騎馬旗。**不可下馬**、預置馬騎僅一隻、伯樂一次性。
- **REPLACE 保留 ref**（spike_replace 實證：保留 ref、不觸發 DESTROY、效果通道照舊、駐容器中替換有效）
  → 上馬後第 2 命起的馬形態身體沿用命 ref，掛字規則**自動涵蓋**，零特殊處理。
- 顯示缺口僅剩：騎**預置馬騎**那一段（上馬那一命、每場至多一次），且僅限**沒有馬設定器的狀態**
  （醉酒／船暈等——原作設定器條件走步行 ref，本就幾乎打不到騎馬者）。萬一經零條件寫入器＋區域型父觸發
  被騎馬者觸發：狀態牌會寫、頭上不顯示，首次馬死後自癒。s51 把「零條件寫入器＋其直接父觸發」
  列成報告項（不擋建置）供逐一檢視。

## 五、規模與把關

- 附掛 caption ≈768 個效果＋清字 180 個效果（72＋108），0 支新觸發。
- log：`logs/51_狀態字幕.tsv`（每筆附掛/清字一列：觸發、原文、頭頂文、目標 ref）。
- **s90**：頭頂文字全走字型缺字關（狀態牌原文既存檔內，字元集風險低；「懾」等罕字若真缺，照 s85 裁決流程換字）。
- **s91 特徵斷言**：①768 個狀態牌寫入各有尾隨 caption 且數量對帳；②72 支重生 timer、108 支上馬拷貝各帶清字；
  ③掃描相異文字 ⊆ 裁決表；④牌 ref→職業推導與定案表一致。
- 測試指引（test_guide）：選角後找毒物碰英雄 → 頭上出「中毒 2秒-100精力」＋狀態牌同步；走解毒區 → 頭上清空；
  死亡重生 → 新身體頭上必乾淨（含毒未解時）；上馬後再中毒（碰 X毒3 條件）→ 馬頭上出字。
  陽性對照：狀態牌本身照舊改名（原作行為未動）。

## 六、已知限制（皆與原作同級或繼承）

1. 多狀態互蓋：一顆物件一條 caption，後到蓋前——狀態牌單格本就同此行為，一致。
2. 狀態字依視野不依所有權：看得到該英雄的玩家都看得到（與職業標示相同）。
3. 騎預置馬期間無馬設定器的狀態不顯示（見§四，窗口有限、自癒）。
